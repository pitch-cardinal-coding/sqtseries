What it is

A live page the service serves itself, at /dashboard on the HTTP port. It shows the health of the service — not your data — pushed over a WebSocket once a second.

Words used on this page

Snapshot — everything, once, on connect.
Tick — the counters, once a second, without the lists.
Event — a frame the moment a connection or subscription changes.
Registry — the service's record of who is connected. The dashboard only reads it; it never changes it.
Fallback snapshot — what the page shows if the service's own stats provider is unavailable, so a failing provider degrades the page instead of freezing it.

The service prints the URL when it starts, and sqtseries status prints it again with the ports it is actually on.

What it shows

Health

Whether the database is reachable and whether the service has finished starting. This is the one panel to watch when something is wrong, and it is the first thing to check before reading any counter.

Ingest

CounterMeansAlert when
ingestedPoints accepted for storage, both transports falls when it should rise
persistedPoints actually committed trails ingested — normal while work is in flight
droppedPoints in a batch whose insert failed any sustained rise — the database is refusing writes
invalidFrames refused as malformed, or breaching the clock-skew window any sustained rise — usually a producer's clock has drifted
ingest_errorsSocket-level receive errors any rise at all
The accounting identity

Every accepted point lands in exactly one of persisted, dropped or invalid. Nothing vanishes silently, so ingested - persisted is exactly the work still in flight, and any permanent loss shows up as a non-zero dropped rather than as a gap you have to infer later. The test suite asserts this identity, so a regression that broke it would fail a test rather than quietly losing your data.

Queries

queries, query_errors, queries_shed and replies_dropped. Two of these are easy to misread:

Shed is backpressure, not failure

queries_shed counts requests that were not dispatched because query.max_inflight was already reached. The request stays in the socket pipe, bounded by the socket's own HWM, and is served when capacity frees. It was deliberately not dropped — it is queued and counted.

So a rising queries_shed means your clients are outrunning the query budget, not that anything failed. The response comes back late. If you are seeing it, you want more query capacity (max_inflight) or fewer polling clients — not a faster disk.

replies_dropped is different: it counts replies that found no peer, because the requester disconnected mid-flight. Harmless in small numbers, worth investigating if it climbs.

Storage

Database size on disk, partition count, WAL size, and the rollup watermark — the next hour the rollup will process, in nanoseconds. The watermark sitting still while ingested climbs is correct: the current hour is never rolled.

Connections and topics

Every live WebSocket connection with its peer address, topic, arrival time and last activity. And every topic ever seen, with its live subscriber count and its per-topic publish total.

Why a quiet topic does not disappear

The topics list is append-only: a topic that has gone quiet reports subscribers: 0 and keeps its first_seen time, rather than vanishing. When you are working out whether a producer stopped, that is exactly the difference you need — a vanished row and a zero row are different facts. Stored metrics that nobody subscribes to are also listed, at zero.

The tick deliberately omits connections and topics. Re-sending a list every second would be waste, since every change in those lists already arrives as its own event as it happens.

Consuming it yourself

# in a browser console, on the host running the service
>>> ws = new WebSocket("ws://127.0.0.1:12505/ws/dashboard")
>>> ws.onmessage = e => {
...    const m = JSON.parse(e.data);
...    if (m.type === "tick") console.log("ingested", m.ingested, "dropped", m.dropped);
...    else if (m.type === "conn") console.log("client", m.connected ? "joined" : "left", m.peer);
...    else if (m.type === "sub") console.log("topic", m.topic, m.subscribers);
...    else if (m.type === "snapshot") console.log("uptime", m.uptime_s, "ports", m.ports);
...  }

The queue between the event listener and the sender is bounded at 500 frames. A browser tab that stops draining — backgrounded, or on a slow link — loses the oldest frames rather than growing the server's memory without limit.

The page itself

Worth knowing because it explains what you can and cannot inspect from the browser.

QuestionAsk
Is the service up?GET /api/v1/health
What are the real ports?sqtseries status or the ports key in the snapshot
How many points are stored?GET /api/v1/stats
Who is connected?GET /api/v1/connections, or the connections admin command
Who is watching what?GET /api/v1/subscribers, or the subscribers admin command
Is a specific id still there?the conncheck admin command, which is a cheap membership test
Everything, livethe dashboard page, or /ws/dashboard consumed directly
Do not scrape the page for monitoring

The dashboard is a view. Everything on it is available as JSON over the admin socket or the HTTP API, and those are the surfaces to alert on: a polling check on /api/v1/health plus a read of stats will not break when the page's markup changes, and it will not need a browser on the monitoring host.

Why there is no CDN

The gateway sets a strict Content-Security-Policy on every response: default-src 'self'. A browser-enforced policy cannot be relaxed by the page, so a page that loaded its fonts or scripts from a CDN would simply be blocked on this host.

So everything is vendored and served from this origin:

PathWhat
/dashboard, /the page
/dashboard-assets/dashboard.jsthe feed consumer
/dashboard-assets/dashboard.cssits styling
/dashboard-assets/nucleo-icons.*the icon font, local
/dashboard-assets/specs/*the vendored Swagger and ReDoc bundles
/api-docsSwagger UI, reading /openapi.json
/redocReDoc, same schema
/docsthese pages

Those three pages — Swagger, ReDoc and these docs — are also why the gateway sets a path-scoped CSP exception for /docs: these pages inline their stylesheet so a single file stays readable on its own, and an inline <style> needs an explicit style-src. The relaxation covers styles only, on that one path. The JSON API keeps the strict default above, and script-src is not relaxed anywhere.

No client library. Nothing to generate.

The wire format is four fields in and a status envelope out. If your language can send JSON over HTTP or ZeroMQ, it already speaks sqtseries. There is no IDL, no code generation, and no SDK version to keep in step with the server.

Two rules, and one of them bites

HTTP — start and end are epoch seconds (or an ISO-8601 string), and the timestamp in the reply is epoch seconds.
ZeroMQ — start and end in the request are epoch nanoseconds as an integer (or an ISO-8601 string), and the timestamp in the reply is back to epoch seconds.

Getting the ZeroMQ side wrong returns an empty result, not an error. Seconds where nanoseconds are expected asks for a window in 1970. If a ZMQ query returns nothing while the HTTP one works, this is almost always why — and it is worth checking first.

Which samples were actually run

The Python, Node.js and Rust samples below were executed against a live service on this machine, and their output is real. Pick your transport first

This is the only real decision. Everything after it is a serialisation detail.

HTTPZeroMQ
Needsan HTTP client, which every language has a ZeroMQ binding, which most do not

Subscribe to live dataWebSocketSUB socket
Request unitssecondsnanoseconds in, seconds out

Both converge on the same tables, the same rollup and the same live stream, and the admin counters merge them — so nothing later can tell you which transport a point arrived on. Use whichever fits; use both if you like.

Python

Two options, and the second needs no service at all.

The bundled Client, over ZeroMQ

from sqtseries import Client

with Client() as c:                      # context manager: never leaks a socket
    c.write("cpu.load", 0.42, {"host": "web1"})
    c.write("cpu.load", 0.44, timestamp="2026-09-30T17:00:00Z")

    rows = c.query("cpu.load", start=1691234567000000000, end=1691238167000000000)
    # rows: [{"timestamp": 1691234567.0, "value": 0.42}, ...]  -- SECONDS out

    agg = c.aggregate("cpu.load", start=… , funcs=["avg", "p99"])
    # {"avg": 0.43, "p99": 0.44}

    health = c.admin("health")
    print(c.admin("stats")["persisted"])

    for payload in c.subscribe("cpu.", timeout=0.5):
        if payload is None:
            continue        # idle heartbeat
        print(payload["metric"], payload["value"])

Non-default ports, when your service moved:

c = Client(host="127.0.0.1", ports={"write": 12601, "query": 12602,
                             "subscribe": 12603, "admin": 12604})

Two details the Client handles that are easy to get wrong by hand: the write socket gets a 2 s LINGER so a measurement written just before exit is still delivered, and a REQ socket whose recv times out is dropped and recreated — a REQ socket enforces strict send/recv alternation, so a timed-out one would raise on the next call and stay broken.

The embedded engine, in-process

No sockets, no ports, no service, nothing to supervise. The query code returns nanoseconds here, because there is no gateway doing the conversion.

from sqtseries.engine import StorageEngine, create_sqlite_engine
from sqtseries import TimeSeriesDB

engine = create_sqlite_engine("/tmp/embedded.sqlite")
db = TimeSeriesDB(StorageEngine(engine))

db.insert("cpu.load", 0.42, {"host": "web1"})
db.insert("cpu.load", 0.51, {"host": "web1"})

rows = db.query("cpu.load", aggregation="avg", interval="1h")
# [(timestamp_ns, value), ...] -- NANOSECONDS out

# fill gaps up to 5 minutes by linear interpolation (embedded API only)
rows = db.query("cpu.load", fill_gaps_ns=5 * 60 * 10**9)

# stream without materialising: bounded memory over a huge window
for ts_ns, value in db.query_stream("cpu.load"):
    ...

db.close()
engine.dispose()

Node.js and the browser

fetch for writing and querying, WebSocket for live data. Node 22+ has all three built in, so there is nothing to install.

// write.mjs — Node 22+, no dependencies
const BASE = "http://127.0.0.1:12505";

const write = async (metric, value, tags) => {
  const res = await fetch(`${BASE}/api/v1/write`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ metric, value, tags }),
  });
  return res.json();          // {"status":"ok","written":1}
};

const read = async (metric, startSeconds, endSeconds) => {
  const q = new URLSearchParams({
    metric,
    start: String(startSeconds),       // SECONDS over HTTP
    end: String(endSeconds),
    limit: "100",
  });
  const res = await fetch(`${BASE}/api/v1/read?${q}`);
  return (await res.json()).data;   // [{timestamp: seconds, value}, ...]
};

const aggregate = async (metric, funcs) => {
  const q = new URLSearchParams({ metric, funcs: funcs.join(",") });
  const res = await fetch(`${BASE}/api/v1/aggregate?${q}`);
  return (await res.json()).aggregations;
};

await write("cpu.load", 0.42, { host: "web1" });
console.log(await read("cpu.load", Date.now()/1000 - 3600, Date.now()/1000));
console.log(await aggregate("cpu.load", ["avg", "max", "p99"]));

// live: close-over topics, and skip the idle keepalive
const ws = new WebSocket("ws://127.0.0.1:12505/ws/subscribe?metric=cpu.");
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === "ping") return;
  console.log(msg.metric, msg.value);
};

Writing from a browser is the same code — but note that a page served from http://localhost:3000 is a different origin from the gateway, so cors_origins has to allow it:

# config.toml
[http]
cors_origins = ["http://localhost:3000"]

Rust

The Content-Type header is not optional

Send Content-Type: application/json or the write is 400, with the unhelpful {"detail":"each write must be an object"}.

The reason is worth knowing. The write route binds its body as a raw value rather than a typed model, so a request with no JSON content type arrives as raw bytes instead of a parsed object — and the validator, quite correctly, refuses it. The identical body gives 200 with the header and 400 without it. This was found by running the sample below, not by reading it.

The sample uses ureq 3.x, whose API differs from 2.x: in 3.x the request builder is a free function (ureq::post, ureq::get) and the body is read with response.body_mut().read_json::<T>(). A 2.x sample would use ureq::agent() and into_json() instead.

// Cargo.toml — ureq 3.x
[dependencies]
ureq       = { version = "3", features = ["json"] }
serde_json = "1"
$ cargo add ureq --features json
$ cargo add serde_json
use serde_json::Value;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let base = "http://127.0.0.1:12505";

    // write one measurement — the Content-Type header is REQUIRED
    let body = serde_json::json!({
        "metric": "cpu.load",
        "value": 0.42,
        "tags": {"host": "web1"},
    })
    .to_string();

    let mut res = ureq::post(&format!("{base}/api/v1/write"))
        .header("Content-Type", "application/json")
        .send(body)?;

    println!("{}", res.body_mut().read_json::<Value>()?);
    // {"status":"ok","written":1}

    // read: SECONDS over HTTP
    let now = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)?.as_secs();
    let url = format!(
        "{base}/api/v1/read?metric=cpu.load&start={}&end={}&limit=100",
        now - 3600, now
    );
    let data: Value = ureq::get(&url).call()?.body_mut().read_json()?;
    println!("{}", data["data"]);

    // aggregate several functions in one pass
    let agg = ureq::get(&format!("{base}/api/v1/aggregate?metric=cpu.load&funcs=avg,max,p99"))
        .call()?.body_mut().read_json::<Value>()?;
    println!("{}", agg["aggregations"]);

    Ok(())
}

The ZeroMQ shape is the same JSON over a PUSH socket. The one thing to watch is the unit — the request wants nanoseconds:

use zmq::const::SocketType;

let ctx = zmq::Context::new();
let sock = ctx.socket(SocketType::PUSH).unwrap();
sock.set(zmq::LINGER, 2000).unwrap();      // before connect, or it is ignored
sock.connect("tcp://127.0.0.1:12500").unwrap();

let msg = json!({
    "metric": "cpu.load", "value": 0.42,
    "tags": {"host": "web1"},
});
sock.send(&serde_json::to_string(&msg).unwrap()).unwrap();

// query: REQ socket, NANOSECONDS in, seconds out
let req = ctx.socket(SocketType::REQ).unwrap();
req.set(zmq::RCVTIMEO, 30_000).unwrap();
req.connect("tcp://127.0.0.1:12502").unwrap();

let now_ns = 1789000000_000_000_000u64 * 1000;
req.send(&serde_json::to_string(&json!({
    "metric": "cpu.load",
    "start": now_ns - 3_600_000_000_000u64,   // nanoseconds
    "end":   now_ns,
})).unwrap()).unwrap();

let reply: Value = serde_json::from_str(&req.recv_string().unwrap()).unwrap();
println!("{}", reply);

Go

The standard library covers HTTP completely. ZeroMQ needs github.com/pebbe/zmq4 — or github.com/go-zeromq/zmq4 for the modern API. Neither is installed on this machine, so this sample was written against the same wire format as the three that were run.

// HTTP: standard library only, no go.mod dependency at all
package main

import (
    "bytes"
    "encoding/json"
    "fmt"
    "io"
    "net/http"
    "net/url"
    "strconv"
    "time"
)

const base = "http://127.0.0.1:12505"

type Row struct {
    Timestamp float64 `json:"timestamp"`   // SECONDS out
    Value     float64 `json:"value"`
}

func write(metric string, value float64, tags map[string]string) error {
    payload, err := json.Marshal(map[string]any{
        "metric": metric, "value": value, "tags": tags,
    })
    if err != nil { return err }
    res, err := http.Post(base+"/api/v1/write", "application/json", bytes.NewReader(payload))
    if err != nil { return err }
    defer res.Body.Close()
    body, _ := io.ReadAll(res.Body)
    fmt.Println(string(body))   // {"status":"ok","written":1}
    return nil
}

func read(metric string, start, end time.Time) ([]Row, error) {
    // SECONDS over HTTP
    q := url.Values{}
    q.Set("metric", metric)
    q.Set("start", strconv.FormatInt(start.Unix(), 10))
    q.Set("end", strconv.FormatInt(end.Unix(), 10))
    q.Set("limit", "100")

    res, err := http.Get(base + "/api/v1/read?" + q.Encode())
    if err != nil { return nil, err }
    defer res.Body.Close()

    var out struct {
        Data []Row `json:"data"`
    }
    return out.Data, json.NewDecoder(res.Body).Decode(&out)
}

func main() {
    _ = write("cpu.load", 0.42, map[string]string{"host": "web1"})
    rows, _ := read("cpu.load", time.Now().Add(-time.Hour), time.Now())
    fmt.Println(rows)
}
// ZeroMQ: go get github.com/pebbe/zmq4
import zmq "github.com/pebbe/zmq4"

sock, _ := zmq.NewSocket(zmq.PUSH)
sock.SetLinger(2000)                 // before connect
sock.Connect("tcp://127.0.0.1:12500")

body, _ := json.Marshal(map[string]any{
    "metric": "cpu.load", "value": 0.42,
})
sock.Send("json", []byte(body), 0)

// query: REQ, NANOSECONDS in
req, _ := zmq.NewSocket(zmq.REQ)
req.SetRecvTimeOut(30 * time.Second)
req.Connect("tcp://127.0.0.1:12502")

nowNs := time.Now().UnixNano()          // nanoseconds — the whole difference
q, _ := json.Marshal(map[string]any{
    "metric": "cpu.load",
    "start":  nowNs - 3600*int64(time.Second),
    "end":    nowNs,
})
req.Send("json", q, 0)
reply, _ := req.Recv(0)
fmt.Println(string(reply))

PHP

PHP has no ZeroMQ extension in common use, so HTTP is the path. The two calls below need only cURL, which is enabled in almost every PHP build. Not installed on this machine, so this sample was written against the same wire format as the three that were run.

// write.php
<?php
function sqt(string $path, array $query = [], ?array $body = null): array {
    $url = 'http://127.0.0.1:12505' . $path;
    if ($query) { $url .= '?' . http_build_query($query); }

    $ch = curl_init($url);
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT        => 30,
        CURLOPT_HTTPHEADER     => ['Content-Type: application/json'],
    ]);
    if ($body !== null) {
        curl_setopt($ch, CURLOPT_POST, true);
        curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($body));
    }

    $raw = curl_exec($ch);
    if ($raw === false) { throw new RuntimeException(curl_error($ch)); }
    $status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);

    return ['status' => $status, 'body' => json_decode($raw, true)];
}

// write one measurement
print_r(sqt('/api/v1/write', [], [
    'metric' => 'cpu.load',
    'value'  => 0.42,
    'tags'   => ['host' => 'web1'],
]));
// ['status' => 200, 'body' => ['status' => 'ok', 'written' => 1]]

// read: SECONDS over HTTP
$now = time();
$res = sqt('/api/v1/read', [
    'metric' => 'cpu.load',
    'start'  => $now - 3600,
    'end'    => $now,
    'limit'  => 100,
]);
foreach ($res['body']['data'] as $row) {
    printf("%s = %.2f\n", date('H:i:s', (int) $row['timestamp']), $row['value']);
}

// aggregate several functions at once
$agg = sqt('/api/v1/aggregate', [
    'metric' => 'cpu.load',
    'funcs'  => 'avg,max,p99',
]);
print_r($agg['body']['aggregations']);

The shell

curl is enough for writing and querying. For the live stream from a script, websocat is the shortest option, and any language with a WebSocket client works just as well.

# write
curl -s -X POST http://127.0.0.1:12505/api/v1/write \
  -H "Content-Type: application/json" \
  -d '{"metric":"cpu.load","value":0.42,"tags":{"host":"web1"}}'

# read — seconds in and out
curl -s "http://127.0.0.1:12505/api/v1/read?metric=cpu.load&limit=10"

# aggregate
curl -s "http://127.0.0.1:12505/api/v1/aggregate?metric=cpu.load&funcs=avg,min,max,p99"

# health, for a script to branch on
curl -fsS http://127.0.0.1:12505/api/v1/health >/dev/null && echo "up" || echo "down"

# live stream
websocat "ws://127.0.0.1:12505/ws/subscribe?metric=cpu."

# a sustained pump, for a load test
for i in $(seq 1 10000); do
  curl -s -X POST http://127.0.0.1:12505/api/v1/write \
    -H "Content-Type: application/json" \
    -d "{\"metric\":\"cpu.load\",\"value\":$((i % 100)),\"tags\":{\"host\":\"web1\"}}" >/dev/null
done

That last loop makes 10,000 separate HTTP requests, which is slow on purpose — it is the simplest way to prove the path works. For a real sustained rate, use a ZeroMQ producer: the high-rate ingest example does exactly that.

Writing your own client

You do not need any of the above. The contract is small enough to hold in your head, and if you are writing a client in a language with no sample here, these four points are the whole thing.

  1. WritePOST JSON {"metric","value","tags"?,"timestamp"?} to /api/v1/write, or send the same object as one ZeroMQ PUSH frame. Read {"status":"ok","written":N}.
  2. QueryGET /api/v1/read?metric=… with start, end, aggregation, interval, limit, order. Get {"status":"ok","data":[{"timestamp":seconds,"value":…}]}.
  3. AggregateGET /api/v1/aggregate?metric=…&funcs=avg,max,p99 for several functions in one pass. Get {"status":"ok","aggregations":{"avg":…,"max":…}}.
  4. SubscribeWebSocket /ws/subscribe?metric=…, or SUB on 12503 with two-part frames. Skip the {"type":"ping"} keepalive.

Exact field names, defaults, status codes and error codes are on API Reference. Every one of them is verified against the running code by verify_docs.py.

How to read this codebase

Eight thousand six hundred lines, five packages, one entry point. This page maps every module to the job it owns, and gives an order to read them in when you are about to change something.

The one rule that shapes the layout

Only service.py knows the whole picture. It decides the start-up order, which socket binds when, what each background task is given, and what happens on shutdown. Every other module can be read and tested in isolation; this one cannot, and it is deliberately the only one that is allowed to depend on all the others.

Two boundaries are load-bearing, and crossing one is a signal that the change belongs somewhere else:

BoundaryRule
engine knows nothing about the network It has no import of messaging or gateway. It is a database with opinions about SQLite, and nothing else.

Top level

The modules that know about everything else, and the ones you touch first.

ModuleLinesWhat it owns
service.py740 Start here. The start-up sequence in order, the port resolution, the pump loop, the query and admin handlers, the dashboard snapshot, and the ordered shutdown. The only module that imports all the others.
config.py460 Every setting, as pydantic models with their own defaults. The four-level precedence logic, the file readers for TOML/YAML/JSON, and validate_settings — the list of rules that refuse a bad value at start-up rather than halfway through a run.
cli.py410 Eleven click commands. Resolves the global flags, refuses to start over a database another instance is serving, refuses to stop the wrong one, and prints the links. Deliberately thin: each command imports its own subsystem lazily so --help is instant.
client.py367 The bundled Client for Python. Wraps PUSH, REQ and SUB. The details it handles for you: a 2 s write LINGER, and recreating a REQ socket whose recv timed out, because REQ enforces strict alternation and would otherwise stay broken for the socket's life.
systemd.py243 Renders and installs the unit file. The interesting part is _installing_user: under sudo, ~ expands to /root before the module sees it, so a default path would put the database in root's home. It resolves the real user and re-anchors the path.
logging.py79 structlog configuration, console or JSON, optional file output.
ports.py71 PortAllocator. Probes by binding and closing, which is race-tolerant: if something takes the port in the gap, the real bind fails cleanly rather than misdirecting a client.
runtime.py55 Read and write runtime.json: pid, version, database path, and the ports actually bound. The reason status can report the real ingest port rather than the configured one.
recovery.py41 Startup integrity check and WAL recovery.
health.py31 The health payload, shared by the CLI, the admin socket and /api/v1/health.
__main__.py4 So python -m sqtseries works identically to the console script.

messaging — the sockets

Everything that touches a ZeroMQ socket, plus the wire format and the registry.

ModuleLinesWhat it owns
ingress.py340 The write path. PULL socket, batched NOBLOCK drain, validation, and the bounded hand-off to the persister. The subtle parts: the counting semaphore that bounds queued plus in-sink batches (a bare maxsize queue would not count the batch the persister has taken but not finished), and a shutdown that sweeps the socket before closing it, because libzmq discards undelivered frames on close.
connection_registry.py288 Who is connected. Thread-safe, emits conn and sub events to any number of listeners, and every registration must be paired with a remove_listener or the list grows without bound across start/stop cycles. The topic list is append-only, so a quiet topic reports zero rather than disappearing.
broker.py257 The query and admin responder. ROUTER rather than REP, so concurrent clients are served in parallel instead of serialising — measured with 8 REQ clients: REP gave p50 of about 1.1 s, exactly eight times the handler time. router_mandatory is on so a reply to a vanished peer is counted rather than silently dropped.
pubsub.py217 The XPUB stream socket and its subscription tracker. Sets XPUB_VERBOSER, without which a second subscriber to an already-known topic produces no event and the count is wrong — verified on libzmq 4.3.5. Also holds the fan-out hub.
protocol.py205 The wire format. parse_ingest, parse_query, parse_admin, and iso_to_ns with nanosecond precision. Contains the rule that server-assigned timestamps are forced strictly increasing, because the wall clock is coarser than a burst and a duplicate nanosecond would violate the primary key and roll back the whole transaction.
fanout.py195 The in-process path to WebSocket subscribers, with a byte-bounded queue each. Holds topic_matches, where the boundary rule lives — a plain prefix match fanned stress.m1 out to stress.m10 and friends, about 7× amplification under stress traffic.
query_cache.py157 A bounded LRU with per-entry TTL. Bounded by weight (total rows), not just entry count, because a count-only bound let cached 100k-row results grow the heap by about 5 MB per second. A single result larger than the budget is never cached at all.
stats_publisher.py122 The stats PUB socket on 12506. A comment records that CONFLATE was tried and reverted, because it collapses multipart frames to their last part and corrupts the [topic, payload] format.
context.py90 Socket option defaults. LINGER is set here, before bind, per pyzmq guidance. TCP keepalive as a second net behind ZMQ heartbeats, which only fire while frames are exchanged.
worker.py77 The pump loop. Sleeps longer when idle rather than busy-polling, because a NOBLOCK loop that only yields via sleep(0) keeps the loop thread re-taking the GIL and starves the CPU-bound worker threads.

engine — the file

Everything that touches SQLite. No network imports anywhere in here.

ModuleLinesWhat it owns
db.py535 The connection layer. One persistent writer behind a lock, a LIFO reader pool, and a self-healing writer that is quarantined and replaced if a transaction fails. Contains the check-in hygiene that matters most: every cursor is closed at check-in, because a partially-consumed SELECT holds a WAL read snapshot even outside a transaction and would block a TRUNCATE checkpoint indefinitely. The module docstring records the research behind the pooling design and the LIFO choice.
store.py527 The storage API above the raw layer: series resolution, batched inserts, time-range reads, downsampling inside SQLite, and the partition cache. The CUD funnel — every create and delete converges on StorageEngine.insert_many.
backup.py136 VACUUM INTO snapshots, the filename scheme, and the background manager. The docstring lists SQLite's own caveats — the destination must not exist and it cannot run inside a transaction.
checkpoint.py131 The WAL checkpoint timer, and the busy counter that reveals a long reader blocking checkpoints.
migrations.py71 A versioned, idempotent migration runner, plus creating the current month's partition. A schema_version table, because SQLite's ALTER support is too limited for most changes.
schema.py67 The DDL, and the partition-name helpers. Contains a real precision trap: computing the month from ts_ns / 1e9 is float division, which loses precision past 2^53 and can round the last nanosecond of December into January. It uses integer arithmetic instead.
maintenance.py55 The periodic ANALYZE task.
pragmas.py49 PRAGMA helpers: optimize, checkpoint, quick_check, integrity_check, incremental_vacuum, analyze.
__init__.py40 The package's public surface.

query, partition, gateway

ModuleLinesWhat it owns
query/builder.py577 The query facade. TimeSeriesDB: raw reads, whole-window aggregates, bucketed downsample, gap filling, and the rollup fast path. Also max_rows enforcement, which is a cheap COUNT(*) before the fetch so an over-cap query is never charged for rows it will not return.
query/agg.py217 The ten aggregations, interval parsing, bucketing, and linear gap filling. Empty windows are defined per function — count and sum are 0.0, the rest are NaN — so an empty result never raises StatisticsError.
partition/rollup.py338 The hourly summary. The watermark, the skew-aware roll-up window, and query_rollup_partial. Documents its own assumption honestly: in-order ingestion for completed hours, and a backfill into an already-rolled hour is not picked up until that partition is rebuilt with replace=True.
partition/retention.py188 The TTL policy, the two duration syntaxes, and the background manager. Dropping a partition also removes its rollup rows, so deleted data leaves no aggregate trace behind.
partition/manager.py72 Creating, listing and dropping monthly partitions, with a DDL lock and name validation before any interpolation into SQL.
gateway/app.py394 The FastAPI app: the three WebSocket endpoints, the dashboard and docs mounts, the self-hosted Swagger and ReDoc, and the middleware stack. The header middleware is raw ASGI rather than @app.middleware("http") on purpose — the decorator wraps every request in a task group and anyio stream, and py-spy showed that dominating stacks under load.
gateway/routes.py378 The seven REST routes. Every write is validated as a whole before anything is stored, and every blocking call is moved off the event loop.
gateway/dashboard.py144 The dashboard feed: snapshot, live events, and a one-second tick that omits the list-shaped keys because those already arrive as events.
gateway/websocket.py118 The three WebSocket handlers, with the 30-second send timeout that evicts a stuck consumer instead of holding its subscription hostage.
gateway/ratelimit.py66 Fixed-window per-peer limiting. Deliberately does not trust X-Forwarded-For — it is client-controlled and would let anyone rotate it to escape the limit. The key table is bounded to 10,000 with FIFO eviction, so IP churn cannot grow memory.

Under gateway/static/ are the dashboard's own HTML, CSS and JavaScript, the vendored icon font, and the Swagger and ReDoc bundles. Everything is local because the gateway's Content-Security-Policy forbids a CDN. THIRD-PARTY.txt records the licences.

Conventions worth matching

If you are contributing, these are the house rules, and the code is more consistent about them than most projects of this size.

RuleBecause
Type hints on every public function strict ruff configuration, and the interfaces are the contract.
Errors are typed, and carry a stable code clients match on the code, not the message, so improving the wording never breaks anyone.
Nothing is swallowed silently a dropped batch, a shed request and a failed backup each increment a counter. An empty except is treated as a defect.
Every bound is a named constant with a reason a bare 1000 in a socket call is unreviewable.
Comments explain why, and cite the measurement a constant is not self-explanatory; "measured 2026-09-09 at 10k pts/s" is. When you change a bound, update the comment with it or delete it — a stale justification is worse than none.
Validate at the edge, trust inside the wire layer validates everything; past it, functions do not re-check what the caller already guaranteed.
Blocking work runs in a thread the event loop must never be waiting on SQLite.
Comments on their own line never a trailing comment after code — except in a SQL string, where the # noqa has to be inline to attach to a line.

Linting and tests

# the project's own targets
make lint          # ruff check + format --check
make test          # the whole suite
make test-docs     # tests/test_docs_claims.py — keeps these docs honest

# or directly
$PY -m ruff check src tests examples scripts
$PY -m ruff format --check src tests
$PY -m pytest tests/ -q
$PY -m pytest tests/test_query.py -q -k rollup   # one thing, fast

Every suite uses a temporary database under tmp_path and OS-assigned free ports, so the tests never conflict with a running service or with each other. timeout = 60 is global, so a hang fails rather than waiting forever.

Where a change belongs

Most bugs in a codebase like this one land in the same few places. This is the map.

SymptomLook first at
Points arrive but are not stored ingress.py — the backpressure state and stats() — then service._sink for the drop counter
A write stalls the whole service anything blocking the event loop; the bounded queue and the off-loop executor in service.py
Memory grows under load every bound, and the max_rows check in query/builder.py
A query is slow where it should be fast the eligibility test in query/builder.py, and the watermark in partition/rollup.py
A query returns the wrong number the disjointness of the three window sources in _rollup_window_partials, and month_partition_key for a month-boundary rounding
Subscriber counts are wrong XPUB_VERBOSER in pubsub.py, and topic_matches in fanout.py
WAL grows without limit engine/checkpoint.py and the cursor-release path in engine/db.py
A port is not what the config says ports.py and the reservation order in service._start
Restore lost recent data whether a plain file copy was used instead of VACUUM INTO
The service dies on boot under systemd systemd.py — usually ReadWritePaths not covering the data directory

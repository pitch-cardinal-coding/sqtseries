How a setting gets its value

Four sources can set a value. They are applied in a fixed order, so you always know which one wins. A setting the environment touches ignores the file entirely — that is deliberate, and it is why a container variable reliably beats a baked-in config.

  1. The default in the codeEvery setting has one, and it is what you get with no configuration at all. Every default on this page was read out of src/sqtseries/config.py.
  2. The config fileNamed by --config, or by SQT_SERIES_CONFIG_FILE. TOML, YAML or JSON, chosen by suffix.
  3. Environment variablesAnything prefixed SQT_SERIES_. A variable beats the file for the same leaf, always.
  4. --dbApplied after everything else, so it wins over the file and the environment for the database path.
The file does not simply override the environment

Settings loaders usually let an init argument beat an environment variable. Here that would be wrong: a file could shadow a variable that an operator set on purpose. So the loader reads the file, works out which leaves the environment actually set, and then re-applies only the file keys the environment did not touch. A variable therefore always wins, and the file still fills in everything else.

Writing a config file

Format is chosen by suffix: .toml, .yaml, .yml or .json. A missing file is an error, not a silent fall back to defaults.

# config.toml
[database]
path        = "~/.sqtseries/data/db.sqlite"
batch_size  = 2000

[ingestion]
port        = 12501
hwm         = 101000

[query]
port        = 12502
timeout_s   = 30.0
max_rows    = 10000

[http]
host        = "127.0.0.1"   # local-only; the default is 0.0.0.0
cors_origins = ["http://localhost:3000"]

[retention]
default_ttl = "90d"
# equivalent JSON
{
  "database": {"path": "~/.sqtseries/data/db.sqlite", "batch_size": 2000},
  "http":     {"host": "127.0.0.1"}
}

YAML needs pyyaml, which is not a declared dependency. TOML is built in and JSON goes through orjson; if you want YAML, install pyyaml or use TOML.

Environment variables

The prefix is SQT_SERIES_. Nest one level with a double underscore, so http.rate_limit_per_minute becomes:

$ export SQT_SERIES_HTTP__RATE_LIMIT_PER_MINUTE=42
$ export SQT_SERIES_DATABASE__BATCH_SIZE=500
$ export SQT_SERIES_CONFIG_FILE=/etc/sqtseries/config.toml

Names are case-insensitive, and an empty value counts as unset. So SQT_SERIES_DATABASE__PATH= with nothing after the equals means "use the default", not "use an empty path".

Ports, and why ingest is not the one you set

Six ports, five fixed and one chosen at start-up. This surprises almost everyone, so it is worth reading before you point a client at a number.

{{ports_table}}

The detector probes each candidate by binding 127.0.0.1 on it, then closing the socket and moving on. It is race-tolerant: if something takes the port in the gap between the probe and the real bind, the bind fails and you get a clean error rather than silent misdirection. The five fixed ports are reserved in the allocator before the detector runs, so it can never hand out one of them.

Running beside something else

Use port_offset to shift the whole detection window, or set auto_detect = false and pin ingestion.port yourself:

# a second instance: detection window 12600-12800
[ports]
auto_detect = true
port_offset = 100

# or pin everything, and fail loudly if it is taken
[ports]
auto_detect = false

[ingestion]
port = 12601

Duration values — two syntaxes

This is the single most common configuration mistake, and it is a mistake because there are two similar parsers with different rules.

Interval stringsTTL strings
Used by rollup.interval, backup.interval, maintenance.analyze_interval retention.default_ttl, retention.check_interval
Units accepted s m h d s m h d w
1m meansone minuteone minute
1w rejectedone week
Granularity of the effect how often the task runs retention drops whole monthly partitions, so a TTL is applied at month granularity whatever it says
There is no month syntax anywhere

Both parsers treat m as minutes. If you want "keep a year of data", write 365d or 52w — not 12m, which keeps twelve minutes and then drops whole monthly partitions, deleting far more than you intended.

[retention]
default_ttl     = "365d"   # a year — this is what you want
default_ttl     = "12m"    # twelve MINUTES — almost certainly a mistake

The database settings

These map onto SQLite's own file-level and per-connection settings. The defaults are what the shipped code uses; the notes explain the ones that look unusual.

{{settings_database}}
Why the page cache default is 8 MB, not 64 MB

The setting says -64000 (64 MB in KiB-negative form), but the code path applies cache_size = -8000 per connection instead, and that is deliberate. A 64 MB cache on a handle shared across executor threads makes glibc arena allocations balloon: pages cached on thread A's arena stay in A even when thread B later runs the same handle, because free() returns memory to its allocating thread's arena. Total resident memory then climbs roughly with threads times working set. Measured on 2026-09-09 at 10k pts/s: 60–100 MB anonymous arena mappings per handle in smaps, and anonymous memory growing about 25 MB per snapshot.

8 MB keeps the hot working set of a steady-state run resident per handle without the cross-thread duplication, and a miss falls through to the OS page cache, which is shared. A transient connection — one opened because every pooled reader is checked out — gets the same 8 MB rather than the full figure.

batch_size has a hard ceiling of 8191

A batch becomes one INSERT with a bound parameter per column per row, so it can run into SQLITE_MAX_VARIABLE_NUMBER. Above 8191 the service refuses to start and says so, rather than failing every burst at 3 a.m.

Background tasks and logging

The rollup, retention, maintenance and backup tasks, and how the service logs. Each task runs on boot and then on its interval, in a worker thread so a long pass never stalls the event loop.

{{settings_tasks}}
Turning a task off changes behaviour, not just timing

rollup.enabled = false is the one to think about. Queries stay correct — the rollup is an accelerator, not a source of truth — but a wide query then scans raw rows instead of summary rows, and that is a large, growing cost. The other three only change how often something tidies up.

What is refused at start-up

Every rule below is checked before the database is opened. A violation is an error naming the key, not a service that starts and then misbehaves.

Every violation is collected, not just the first, so one run tells you everything that is wrong.

A complete config, every key once

Copy this as a starting point. Every key the loader reads is present, in file order, with its shipped default — so anything you change is a deliberate departure from what you just read.

busy_timeout      = 5000

threads           = 4
batch_size        = 2000          # 1..8191; one transaction per batch
flush_interval    = 1.0

[ingestion]
port                        = 12501   # used only when auto_detect = false
hwm                         = 101000
pending_max                 = 100
max_message_size            = 52428800
reject_client_timestamp_skew_s = 300.0  # 0 disables the guard

[query]
port         = 12502
timeout_s    = 30.0          # 504 over HTTP, QUERY_TIMEOUT over ZMQ
max_rows     = 10000          # 0 = unbounded
max_inflight = 64

[streaming]

[admin]
port = 12504

[stats]
enabled = true

Check it before you rely on it

Point the service at the file and ask. ports prints the values that will actually be used, which is the fastest way to catch a typo in a key name — an unrecognised key is ignored rather than reported, so a misspelling fails silently by design.

$ sqtseries --config config.toml ports

Security

Two facts decide how exposed the service is, and both are defaults rather than choices you made.

SurfaceBindsAuthentication
Five ZMQ ports127.0.0.1 only none — the loopback binding is the control
HTTP gatewayhttp.host, default 0.0.0.0 none — any request that reaches the port can read and write
WebSocketssame as HTTPnone

So on an untrusted network, both of these before you start:

[http]
host         = "127.0.0.1"
cors_origins = ["http://localhost:3000"]

That closes the service to the local machine. To serve other machines safely, leave it bound and put a reverse proxy in front that terminates TLS and authenticates. The response headers the gateway sets — X-Frame-Options: DENY, X-Content-Type-Options: nosniff, a strict Content-Security-Policy and a Permissions-Policy that denies camera, microphone, geolocation and payment — are all set on every HTTP response already.

The rate limiter keys on the socket peer address and deliberately does not trust X-Forwarded-For, because that header is set by the client and would let anyone rotate it to escape the limit. Behind a proxy, have the proxy do its own limiting.

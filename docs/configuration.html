Configuration

You do not have to configure anything to start using sqtseries — the defaults work out of the box. When you do want to change something, settings can come from three places. If the same setting appears in more than one, the one lower in this list wins:

  1. Built-in defaults
  2. A config file (TOML / YAML / JSON) passed with --config or SQT_SERIES_CONFIG_FILE
  3. Environment variables (SQT_SERIES_*) — these beat the file

On top of that, the --db command-line flag overrides database.path no matter what the config file or the environment say — the CLI always wins for that one setting.

The CLI: global flags come first

Global flags — --version, --config FILE, --db FILE, --help — belong to the sqtseries command itself and therefore have to come before the subcommand. Putting them after it fails with "No such option":

sqtseries --config c.toml run       # correct
sqtseries run --config c.toml       # ERROR: No such option

The commands, all of which accept --config and --db in front of them:

CommandWhat it does
runStart the service in the foreground. Refuses to start when the same database is already being served, or when a different database in the same directory is live (it names the offending pid and database). Ctrl-C stops gracefully with exit code 0.
stopSend SIGTERM to the running instance (read from runtime.json). Refuses when the runtime database differs from the resolved one.
statusShow pid, version, database path, and per-port lines; warns when the runtime database differs from the configured one.
portsShow the active ports; when not running, show the configured ones (ingest/query/stream/admin/http).
healthRead-only PRAGMA quick_check probe; prints "ok" or "degraded: ...", exits 0/1 accordingly.
statsPrint metric and series counts.
vacuumFull VACUUM (stop the service first).
optimizePRAGMA optimize for query-planner statistics.
backupConsistent snapshot via VACUUM INTO into backup.path.
installInstall the systemd unit; --system targets /etc/systemd/system.
uninstallRemove the systemd unit; --system targets the system unit.

Commands exit 0 on success and 1 on a ClickException (a refused operation or a validation error); bad usage (an unknown flag, e.g. sqtseries run --config x) exits 2; a missing or unparseable config file raises an uncaught traceback and exits 1. health is the exception with its own 0/1 body. The only flags on subcommands themselves are install --system and uninstall --system.

Choosing a database file with --db

The database lives wherever database.path says, but you can override it per command without editing any file:

sqtseries --db /data/tsdb.sqlite run
sqtseries --config prod.toml --db /data/other.sqlite stats

One directory may hold several databases, each with its own runtime.json next to the .sqlite file. sqtseries checks for conflicts before acting:

  • run refuses to start when a live instance is already serving this database (Database ... is already being served (pid N)), or when a live instance in the same directory serves a different database (Conflicting databases: ... — it tells you which pid and which file, and how to point --db at it).
  • run prints a note when other .sqlite files exist in the database directory, suggesting --db to pick one.
  • stop refuses to send SIGTERM to an instance whose database differs from the one the command resolves to; pass that database's --db path instead.
  • status prints a Warning when the running instance's database differs from the one the command resolves to.

Configuration file

Each group of settings has its own section. You only need to list the settings you actually want to change — anything you leave out keeps its default.

# config.toml — a complete example with changed values
[database]
path = "~/.sqtseries/data/db.sqlite"   # db file location
page_size = 8192                        # config-only (fixed 8192 in the engine)
cache_size = -64000                     # config-only (fixed -64000 ≈ 64 MiB)
mmap_size = 268435456                   # config-only (fixed 256 MiB)
busy_timeout = 5000                     # config-only (fixed 5000 ms)
journal_size_limit = 67108864           # config-only (fixed 64 MiB)
threads = 4                             # config-only (fixed 4)
batch_size = 2000                       # config-only; see note below
flush_interval = 1.0                    # config-only; see note below

[ingestion]
port = 12501
hwm = 10000
pending_max = 100                       # validated; unused
max_message_size = 52428800             # 50 MiB
reject_client_timestamp_skew_s = 300.0  # reject timestamps skewed > 5 min

[query]
port = 12502
timeout_s = 30.0                         # see note below

[streaming]
port = 12503
linger_seconds = 30.0

[admin]
port = 12504

[http]
port = 12505
host = "127.0.0.1"
cors_origins = ["*"]
rate_limit_per_minute = 600
max_websocket_connections = 1000

[logging]
level = "INFO"            # DEBUG | INFO | WARNING | ERROR | CRITICAL
format = "console"        # console | json
file = null               # optional log file path (rotating, 10 MB x 5)

[retention]
enabled = true
default_ttl = "30d"
check_interval = "1h"
partition_interval = "month"   # only "month" is supported

[rollup]
enabled = true
interval = "5m"           # how often completed hours are rolled up

[maintenance]
enabled = true
analyze_interval = "1h"   # how often ANALYZE refreshes planner stats

[backup]
enabled = true
interval = "24h"
path = "~/.sqtseries/backups/"

[ports]
auto_detect = true        # free-port auto-detection for the ingest port
port_range_start = 12500
port_range_end = 12700
port_offset = 0

[stats]
enabled = true
port = 12506

Supported suffixes: .toml, .yaml / .yml, .json, chosen by file extension. YAML requires the pyyaml package, which is not a dependency of sqtseries — install it yourself or stick to TOML/JSON when it is missing. Errors are raised as uncaught exceptions (a traceback and exit 1): Config file not found: <path> and Unsupported config file format: <suffix> (use .toml, .yaml, .json). Unknown keys in the file and unknown SQT_SERIES_* environment variables are silently ignored — a typo like batc_size does nothing and produces no warning, so check your spelling.

Commands that touch the database (health, stats, vacuum, optimize, backup) open the database file and therefore create it (and its parent directory) if it does not exist yet — sqtseries health on a never-created database exits 0 ("ok"), because an empty file passes the integrity probe.

Environment variables

Every setting can be set with an environment variable. The naming rule: the SQT_SERIES_ prefix, then the section, then __, then the key — all uppercase:

SQT_SERIES_<SECTION>__<KEY>
SQT_SERIES_DATABASE__PATH         # sets database.path
SQT_SERIES_HTTP__CORS_ORIGINS    # sets http.cors_origins

Variables are case-insensitive, and an empty value means "unset" (the default applies). The special variable SQT_SERIES_CONFIG_FILE selects a config file just like --config would.

# Examples
SQT_SERIES_DATABASE__PATH=/data/tsdb.sqlite SQT_SERIES_QUERY__PORT=14002 sqtseries run
SQT_SERIES_CONFIG_FILE=~/prod.toml sqtseries run

Duration values

Durations like 5m, 1h, 30d are a number plus one of s (seconds), m (minutes), h (hours), d (days). Retention TTLs (retention.default_ttl, check_interval) additionally accept w (weeks), e.g. 4w.

Validation rules

Invalid settings stop startup with a clear message instead of a crash mid-flight:

  • Each of ingestion, query, streaming, admin, http, and stats ports must be 1–65535, and the six must be unique.
  • ingestion.hwm ≥ 1 and ingestion.pending_max ≥ 1.
  • database.batch_size must be 1–8191 (SQLite's safe variable limit).
  • rollup.interval and maintenance.analyze_interval must parse as durations (s/m/h/d, ≥ 1) — validated only when enabled.
  • retention.default_ttl and retention.check_interval must parse as TTLs (s/m/h/d/w) — validated only when enabled.
  • Environment variables are case-insensitive, and an empty value means "unset" so it cannot break parsing.

Port allocation

Only the ingest port is auto-detected. If ports.auto_detect is on (default), run scans [port_range_start, port_range_end] + port_offset and binds the first free port, skipping the query/streaming/admin/http/stats ports along the way (the scan starts at port_range_start, so with defaults the ingest port is usually 12500 — not the configured 12501). The other five ports — query, streaming, admin, stats, http — are fixed: if one of them is already bound at startup, the service fails to start with a port error. port_offset is added to the base range in both modes. With auto_detect = false the configured ingest port is used verbatim; if it is taken, startup fails with a ZMQ bind error (EADDRINUSE).

All raw sockets bind to 127.0.0.1. The final, actually-bound ingest port plus the fixed ports (ingest/query/stream/admin/http/stats) are written to runtime.json (next to the database) and shown by sqtseries ports and sqtseries status.

Notes on some settings

  • Every [database] key except path is config-only: batch_size is validated (1–8191) but not consumed, and page_size, cache_size, mmap_size, busy_timeout, journal_size_limit, threads, and flush_interval are not consumed at all — the engine uses its fixed values (see the PRAGMA tables below). ingestion.pending_max is likewise validated but not consumed. The write path ingests one row per message in its own transaction, so these knobs have no effect today. They exist so a future write path can honor them.
  • ingestion.max_message_size (50 MiB) — frames larger than this are dropped at the socket level (the peer is disconnected) and never ingested.
  • query.timeout_s (30) — answers over the wire can take no longer than this budget. Queries are run off the event loop in a worker thread; if the budget is exceeded the client receives a QUERY_TIMEOUT error instead of waiting forever, and the service stays responsive to other traffic. Set to 0 to disable the server-side budget entirely (queries then run to completion).
  • streaming.linger_seconds (30) — the pubsub subscription tracker's linger window after a topic unsubscribes.
  • backup.enabled/interval — automatic snapshots. The backup manager takes a consistent VACUUM INTO snapshot on startup and then every interval (default 24h), in a background thread. A snapshot younger than the interval is skipped (restarts don't create duplicate backups). On-demand backups are still available via sqtseries backup (CLI) or the admin backup command.

Security

Local-only service. Every socket binds to 127.0.0.1. There is no authentication — never expose sqtseries to a network.
